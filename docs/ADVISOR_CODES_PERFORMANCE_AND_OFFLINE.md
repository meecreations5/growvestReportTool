# Version 0.28.0 - Advisor Identity, Performance and Trusted-Device Offline Access

## Advisor identity changes

### Automatic Advisor codes

Advisor codes are generated by the application in this format:

```text
GV-ADV-0001
GV-ADV-0002
GV-ADV-0003
```

The code is generated when:

- a new Advisor staff invitation is created;
- Advisor capability is enabled for an Admin or Super Admin;
- an existing Advisor-capable staff record without a code is saved; or
- a Super Admin uses **Users & Roles -> Staff Access -> Generate missing codes**.

The sequence is protected by the Firestore document `counters/advisors` and a transaction so two staff records cannot receive the same number.

### Admin and Super Admin acting as Advisors

Application role and Advisor capability are now separate concepts.

- **Role** controls module permissions and record access.
- **Advisor capability** controls whether the staff member can be assigned to Investors, leads, meetings and reports.

The Advisor role always has Advisor capability. A Super Admin can enable it for an Admin or Super Admin from the staff user form. Advisor-capable Admins and Super Admins appear in Advisor assignment lists while retaining their administrative permissions.

## Performance changes

- Workspace search is preloaded during browser idle time instead of waiting for the first search.
- Search data is retained in an in-memory five-minute index, preventing three Firestore queries on every search.
- Concurrent search loads are deduplicated.
- Investor Dashboard reuses the live notification subscription instead of opening a second notification query.
- Upcoming-meeting queries use Firestore Timestamp values consistently.
- Investor notifications are limited to the latest 50 records and ordered by Firestore.
- Frequently used Firestore queries remain bounded with explicit limits.
- Firebase endpoints are preconnected from the application shell.
- Static application assets use cache-first delivery through the PWA service worker.

## Trusted-device offline access

Offline access is disabled by default.

Staff can enable it from:

```text
My Profile -> Performance & offline -> Trusted-device offline access
```

Investors can enable it from:

```text
Investor App -> Profile -> Performance & offline -> Trusted-device offline access
```

When enabled, the browser uses Firestore persistent IndexedDB caching with multi-tab support. It retains records the signed-in user has already opened, including a limited set of recently viewed dashboard, Investor, lead, report, meeting and notification data.

The service worker may retain safe top-level application pages for offline navigation only after trusted-device offline access is enabled. It does not cache API responses, report-detail URLs, uploaded documents or generated PDFs.

Enable offline access only on a private device. Disable it from the same profile card to clear Firestore persistence and private page caches.

## Firebase deployment

Version 0.28.0 adds an Advisor counter rule and an Investor notification index.

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

No Storage Rules deployment or data migration is required.

## UAT checklist

1. Create a new Advisor invitation and confirm a `GV-ADV-####` code is shown.
2. Enable Advisor capability for an Admin and confirm the code is generated automatically.
3. Confirm that Admin appears in lead and Investor Advisor assignment lists.
4. Disable Advisor capability and confirm historical code remains stored but the user is removed from assignment lists.
5. Use **Generate missing codes** for any older Advisor records.
6. Search the same term repeatedly and confirm the second search is noticeably faster.
7. Enable trusted-device offline access and reload the application.
8. Open dashboard, reports, meetings and notifications while online.
9. Disconnect the network and confirm the top-level pages and recently opened Firestore records remain available where supported.
10. Confirm report PDFs, uploaded documents and sensitive API routes are not available from the service-worker cache.
11. Disable offline access and confirm the application reloads with local persistent data cleared.
