# GrowVest v0.34.10 - Release Validation

## Scope

Monthly Report PDF architecture review, report-workflow How-To-Use guidance, and secure-PDF no-goals parity correction.

## Automated validation

Run:

```bash
node scripts/qa/release-audit.mjs
node --check src/components/reports/create/ReportWorkflowShell.js
node --check src/lib/server/reportPdf.js
node --check src/lib/server/reportServer.js
```

## Functional validation

### Report workflow help

- `/reports/create` shows **How to use**.
- `/reports/[reportId]/edit` shows the same guide.
- Guide contains all 10 steps.
- Guide closes with X, backdrop, and **Got it**.
- Existing **Copy Previous** behaviour remains unchanged on desktop for new reports.

### Secure PDF parity

Test one report with goals and one without goals.

With goals:
- cover shows Overall Goal Progress
- executive summary shows goal target and progress bar

Without goals:
- cover shows General Wealth Corpus
- executive summary shows General Wealth Corpus
- no goal-progress bar is drawn

### Delivery lifecycle

Verify the sequence:

`Create / Edit -> Save & Preview -> Complete Report -> Generate / Regenerate PDF -> Verify PDF -> Publish -> Send to Investor`

Published versions must remain immutable. If report data changes after PDF generation, regenerate the PDF before publishing.

## Visual redesign regression rule

For the next PDF design pass, compare both outputs for the same report/template snapshot:

1. Browser A4 preview from `/report-print/[reportId]`.
2. Secure downloaded PDF generated by `src/lib/server/reportPdf.js`.

Do not approve a redesign if the two outputs materially disagree on hierarchy, labels, visible sections, branding or totals.

## Environment note

A full Next.js build and live PDF render require the project's npm dependencies. In the code-review environment, dependency installation may be unavailable; if so, complete build/runtime PDF verification in the normal development environment before production deployment.
